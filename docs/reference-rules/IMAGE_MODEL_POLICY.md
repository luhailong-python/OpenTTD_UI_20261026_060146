# 统一图像模型与最高画质策略

## 唯一设置入口

**以后升级默认设置只改 [config/image-generation.json](../config/image-generation.json)。** `model` 是可显式调用的 GPT Image 型号，`quality` 是该型号经官方核实的最高画质；`builtin_product` 记录宿主产品名称，`verified_on` 和 `sources` 记录核对日期及官方依据。各 MD、技能及本机已适配 CLI 均引用此文件，不各自保存默认版本。逐图记录保存当次设置的历史快照，不是另一份默认设置。

**2026-09-21 用户明确要求：以后出现更高质量，就用最高质量出新图，并记录每张图使用的 GPT Image 版本。** 每个新生图或 AI 编辑任务先读配置并核对官方最新正式版本、最高能力型号与最高质量。发现更新的正式型号，或当前型号新增更高质量档位，且入口支持时，直接更新这一文件及其核对信息用于新图，无需为此偏好再次确认。最高质量随官方能力更新，不固定为某个旧档位名称，也不以自动质量代替可明确选择的最高档。

同一批次沿用启动时核实的设置；获知升级后，后续新批次使用更新设置。用户本次明确指定其他模型或画质时优先，既定美术风格继续保持。此流程在作图前执行，不是后台定时更新服务；API／CLI 的入口授权仍按下文规则。

## 官方开放范围与实际参数

2026-09-18 核对 [OpenAI 发布公告](https://openai.com/index/introducing-chatgpt-images-2-5/)：Images 2.5 已面向各档 ChatGPT、ChatGPT Work 和 Codex 用户在桌面、移动及网页入口开放；API 的 Sunburst 用于更精细的创作，支持 `max`，见[官方模型说明](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst)。当前具体默认值读取配置；本段是核对记录，不是第二份默认值。

此前旧帮助页仍写旧内置型号；这不能推翻发布公告，也不能据此阻止已授权的内置生图。当前会话工具只开放提示词与参考图，不开放 `model`、`quality`。产品已开放不等于本次调用显式锁定了 API 的 Sunburst 分支或 `max`。

## 调用规则

1. **内置优先。** 用配置中的产品及最高画质为目标进行创作；工具有选择器时传入真实 `model` 与 `quality`，没有时继续使用宿主管理入口。无需为内置路径配置 API Key，也不因缺少选择器反复请求已给予的绘图授权。
2. **区分目标与结果。** 无参数时，提示词中的型号／画质只是目标；实际记录为宿主管理，保留工具结果和来源信息。有可靠证据表明本次仍返回旧型号时如实报告；历史图片的型号不能自动代表新调用，也不能重标为新版。
3. **明确参数的 API/CLI。** 仅在用户已选择该备用入口时运行，默认读取同一配置并实际发送其 `model`、`quality`。账号权限与单独计费条件仍需满足；配置本身不表示已完成实际 API 调用验证。
4. **最高质量与尺寸分别处理。** 按当前官方能力设置质量和原生尺寸；输出或拼接为大画布不等于 API 原生分辨率。参数不支持或配置损坏时清楚报错，不静默换成旧模型或低质量。
5. **历史记录保真。** 旧任务说明中记录的来源、实际质量、C2PA、receipt、提示词和 API 授权历史保留。后续生成以本策略和配置为准。

## 逐图生成记录

图片保留范围以 [AGENTS.md 的素材保留规则](../AGENTS.md)为准。2026-09-23 用户已允许删除原图和回退版本；原图移除后保留下面的来源文字、哈希和实际型号证据，另在清理记录注明已删除。来源记录不代表原图仍可读取，也不能将历史审核当作当前像素复验。

从本次要求起，**每张新生成或 AI 编辑的图片，包括候选稿和重试版本，都必须有可对应到该文件的生成记录**。优先保存为图旁的 `<图片文件名>.generation.json`（例如 `01-mail.png.generation.json`）；已有 `source/generation.json` 或 manifest 的目录可沿用原结构，但每个输出必须有独立条目，不能只在整批 README 写一次模型名。

| 记录项 | 必须保存的内容 |
|---|---|
| 图片身份 | `file`、`sha256`、`generatedAt`（含时区）、实际原生 `width`／`height`／`format`；重试和不同版本分别关联 |
| 使用入口 | `tool`、`route`（内置／API／CLI）；工具返回的调用或结果 ID 如有则保存 |
| 当次目标 | `configSnapshot`：复制当次配置的 `model`、`quality`、`builtin_product`、`verified_on` 和 `sources`，不能只引用日后会变化的配置路径；用户显式覆盖另记 |
| 实际提交 | `submittedParameters.model` 与 `submittedParameters.quality`；仅填真实参数，工具无选择器时为 `null`，并记明参数未开放 |
| 实际版本与质量 | `actualModel`、`actualQuality`：只填本次结果或可靠来源元数据明确给出的值；返回了快照版本就原样保存，只返回系列名就只记录系列名，未知为 `null` |
| 确认依据 | `evidence` 保存工具结果、receipt 或 C2PA 等来源记录路径及对应字段；无法确认的字段在 `unverifiedReason` 写明“宿主管理，工具未披露／无可核实元数据” |
| 创作输入 | `prompt` 保存实际提示词文件路径；`references` 保存参考图路径与各自用途；编辑任务另关联编辑前图片及其记录 |

配置值、提示词、实际发送参数及官方开放公告各有用途，均不能代替实际返回版本的证据。即使不能确认实际版本，也要逐图保留当次目标和调用记录，明确写“未确认”，不能空缺后默认视为最新版。交付 README 增加图片到生成记录的索引，让用户能查到每张图的 GPT Image 版本和质量，以及哪些信息尚未披露。

裁切、缩放、拼接、去背景等未再次调用生成模型的派生图，记录 `derivedFrom`（原图路径、SHA256 和生成记录）及 `operation`，由此追溯原始模型与质量；多来源拼接逐一列出来源，不把后处理记成新模型生成。原生尺寸与导出尺寸分别记录。

升级配置或重新生成时保留旧图对应的原记录，新文件建立新记录，避免覆盖后失去版本对应关系。历史图片仅按已有可靠证据补记；没有证据的写“历史未记录／无法核实”，不得按当前配置回填版本。本规则的完成标准是：每张本次新增图片都能查到自己的记录或完整来源链，已知版本有证据，未知版本有明确原因。

## 本机 CLI 如何找到这一文件

已适配入口按以下顺序读取配置：

1. `GPT_IMAGE_CONFIG` 指定的 JSON 路径（需要临时切换配置时使用）。
2. 当前工作目录及父目录中的 `config/image-generation.json`。
3. `~/.codex/image-generation-config.json` 的 `config_path`。本机已注册到本项目；这是路径登记，不存第二份模型／画质。

显式 CLI `--model`、`--quality` 优先；普通默认从配置取得，每次运行重新读取。针对某个旧模型的兼容限制、质量映射和参数验证不属于默认值。其他提供商保留自己的模型／部署设置。

适配范围：系统 `imagegen` Python CLI、用户 `gpt-image` 启动器及已安装／源码／build 副本、`baoyu-image-gen` 的 OpenAI 与 Codex 默认入口，以及地图、精灵、设计技能的生图指令。宿主内置工具由技能读取规则，不能靠本地 JSON 注入未开放的参数。

## 移机与升级

同步本配置及项目 MD；用户目录的技能与 CLI 适配不在项目 Git 内，需随工具迁移或重新应用适配，见[安装说明](AI_DESIGN_TOOLS_SETUP.md)。换路径后只更新本机注册文件的 `config_path`，或设置 `GPT_IMAGE_CONFIG`；保留 API 凭证在本机安全配置中。

通常模型升级只改配置的型号、画质和核对信息，其他 MD/技能无需逐个替换。若未来接口增加必填参数或改变协议，仍需相应更新调用代码；修改文本设置不能改变服务端能力。
