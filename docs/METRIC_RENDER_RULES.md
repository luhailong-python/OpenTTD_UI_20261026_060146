# 图表与财务专用排版

实现：`tools/special_metrics.py`，入口 `render_metric(r, im, s)`；由主渲染器完成header后调用，未处理的页面返回None。只负责静态图像排版，不改主渲染器、不实现游戏逻辑。

## 覆盖

10个图表页：65收入、67货运报酬、84产业生产、85城镇货物、138性能监视、139帧时间、145经营利润、146交付运量、147绩效、148公司价值。

4个财务／成绩页：60财务账簿、62基础设施、66绩效分项、92阶段评价。66九项全部显示并带权重进度，不截成6行。

## 数据和单位

公司曲线直接使用catalog季度行值：收入／利润／价值均£，交付货量为混合货物单位，绩效为0–1000分。产业使用吨，城镇旅客使用人，历史帧时间使用ms和秒。性能监视用catalog当前模拟4.2ms、绘制6.8ms和网络0.8ms绘分类柱，帧率60fps独立标示；没有制造时间序列。

货运报酬catalog只给20天的四种报酬。曲线固定同距离／同数量的示例条件，以20天原值为锚：旅客£128、煤炭£82、邮件£146、货物£118。其余天数为单调下降的示意插值，用于体现时效差异，不是OpenTTD结算公式、不用作业务实现。插值参数和全部点位写在`metric-render-models.json`，用于区分原样例与派生示意值。

财务合计由catalog行计算：本年142800−68200−26400−4280=43920；上年118450−62500−14700−4280=36970。现金284560、贷款100000及本年利润43920来自catalog详情。基础设施所列维护费用2480+420+650+4200=7750；catalog未明确周期，画面不加每月／每年。绩效九项23+15+41+50+100+345+37+1+30=642，权重100+100+100+50+100+400+50+50+50=1000。

## 静态验证

14页全部已构图，`metric-layout-check.json`记录文本框和画布范围检查；0画布溢出。实际查看66绩效、67报酬、138性能和60财务四张QA图；财务正负号包含减号与货币符号间隔的解析已核对。源图派生、原生尺寸、模型证据沿主资源链保存。QA图只表示美术排版检查，没有进行Unity验证。
