# Source-height shoreline geometry

Formal pack: `assets/world/terrain/shore-geometry/manifest.json`. Existing native pixels are projected and composited; this work generates no new painting. Unity import and runtime rendering remain unverified.

`water_cmd.cpp:964–978` maps slopes to the eighteen shore sprite slots. The legal mappings are `23→0, 1→1, 2→2, 3→3, 4→4, 27→5, 6→6, 7→7, 8→8, 9→9, 29→10, 11→11, 12→12, 13→13, 14→14, 30→15`. Slots16/EW5 and17/NS10 appear in the lookup but the function explicitly asserts both slopes are prohibited. Flat and half-tile slopes are also prohibited here. Delivery therefore has48 actual climate/posture assemblies and6 explicit no-draw reserved bindings, covering the entire18×3 slot contract without counterfeit placeholders.

The source does not contain a standalone shoreline pixel mask. It selects external base graphics. Our mask is explicitly reconstructed from the natural slope in `landscape.cpp:GetPartialPixelZ`, rather than claimed as an original OpenGFX image mask. A17×17 world-coordinate mesh records both integer source samples and render heights. Outer boundaries and the zero-height contour use the continuous source plane before pixel rounding, preserving straight tile edges. Positive interior heights use integer source samples. The three actual wet-rock contact locations `(4,4), (4,11), (11,9)` retain exact integer height even when rounding reaches zero, preventing a separate rock placement rule from floating above the ground. The compiled-source QA independently compares the actual upstream switch and enum with all4624 recorded samples.

Every state provides `whole`, `land`, `bank`, and nullable `water`; `layers` and `layerOrder` explicitly define `water→land→bank`. Canvas is256×192 with anchor `[128,128]`. The corresponding rock canvas is256×256 with anchor `[128,192]`, so a shore is placed at `[0,64]` under the independent wet-rock layer. The horizontal water layer is restricted to the zero-height face. Native grass, native beach-sand and native snow textures cover positive-height terrain. Existing native grass-bank and sand/foam strip pixels decorate the actual shore boundary; snow uses native water-side foam and keeps the original snow RGB. No procedural line, foam, rock or grass is painted.

`GetFloodingBehaviour` classifies single-corner coast asActive and all other coast asDryOut. The latter have only low-edge/corner contact with the sea and can have no positive-area horizontal water face. Their `water:null` is an explicit geometry result with `waterAbsentReason`, rather than a missing variant or blank placeholder. There is no full flat-water diamond hidden beneath the raised land.

The54 old shoreline PNGs in `infrastructure/water-states` remain byte-identical. Their manifest rows now use `shore-legacy-flat-reference`, `authoritative:false`, no current `sourceRequirementIds`, and `supersededBy` this formal pack. The old coverage mapping retains reference metadata and an empty formal file list. `records/world-production/shore-legacy-retirement.json` records the old PNG hashes and original wrong sequential slope mapping. River/canal/flow-slope resources are untouched. The old `build_world_service_states.py water` shore branch is obsolete and must not be used to regenerate authoritative shoreline artwork.

Inspection entry point: `previews/world/shore-geometry/index.html`. Six pages show every one of the48 actual assemblies; the reserved/no-draw table is included. `tools/validate_shore_geometry.py` checks source mappings, compiled C++ height samples, zero-height water pixels, exact layer recomposition, current native dependencies, transparent RGB, every wet-rock contact and unchanged old PNGs. The parent manager's rock pack references these formal shore layers directly, so it owns the CoastRocks combined previews without producing a second shoreline base.

Source paths also include `water_cmd.cpp:1018–1029` for ClearRocks versus CoastRocks draw order and `rail_cmd.cpp:2100–2130` for the separate foundation/half-tile-water path. Those paths explain the scope boundary; they do not add extra shoreline sprite slots.
